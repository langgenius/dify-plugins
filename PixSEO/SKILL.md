# PixSEO - AI Product Image SEO Optimization

## Overview

PixSEO is an AI-powered e-commerce image SEO optimization engine. It separates image processing (external API) from text generation (local LLM) to ensure data privacy while delivering professional-grade results.

## Architecture & Data Flow

```
┌──────────────────────────────────────────────────────────────────┐
│                        Dify / Coze Agent                         │
│                                                                  │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌───────────┐  │
│  │  User    │───▶│  PixSEO  │───▶│  Local   │───▶│  Response │  │
│  │  Input   │    │  Plugin  │    │  LLM     │    │  to User  │  │
```

### Data Flow Declaration

| Data Type | Processed By | Transmitted to External API? |
|-----------|-------------|------------------------------|
| Product Images | External API (PixSEO) | Yes — for background removal + WebP compression only |
| Alt Text | Agent's Local LLM | No |
| Schema (JSON-LD) | Agent's Local LLM | No |
| Listing Copy | Agent's Local LLM | No |
| API Key | External API (PixSEO) | Yes — via X-API-Key header (SHA256 hashed for storage) |

## Tools

### 1. Process Image (`process_image`)
- **Input**: `image_base64` or `file_url` (one required), `remove_bg` (default: true), `compress` (default: true)
- **Output**: Processed image (base64), size reduction %, elapsed time, step status
- **External API**: POST `/api/v1/process/json`
- **Note**: Does NOT generate alt text, schema, or listing

### 2. Batch Process Images (`batch_process_images`)
- **Input**: `image_urls` (comma-separated) or `image_base64s` (comma-separated), max 10 images
- **Output**: Per-image results with success/failure status
- **Processing**: Parallel via ThreadPoolExecutor (5 workers)
- **External API**: POST `/api/v1/process/json` (one call per image)

### 3. Query API Usage (`get_usage`)
- **Input**: None
- **Output**: Plan name, used count, limit, remaining quota
- **External API**: GET `/api/v1/usage`

## Agent Execution Guidelines

### When to Use Each Tool

1. **Single image uploaded** → Use `process_image`
2. **Multiple images uploaded** → Use `batch_process_images`
3. **User asks about quota/usage** → Use `get_usage`

### Workflow Pattern

```
Step 1: User uploads product image(s)
Step 2: Call process_image or batch_process_images
Step 3: Use Dify LLM node to generate alt text from the processed image context
Step 4: (Optional) Use Dify LLM node to generate Schema/Listing
Step 5: Return combined results to user
```

### Alt Text Generation Template (for LLM Node)

```
Generate an SEO-optimized alt text for the following product image.
The image has been processed: background removed, compressed to WebP.

Product Type: {product_type}
Key Features: {key_features}

Requirements:
- 30-125 characters

- Describe the product, not the background
- Use natural language, avoid keyword stuffing
```

## Known Limitations

1. **Image Format**: Only JPEG, PNG, WebP, AVIF, and TIFF are supported (max 10MB)
2. **Batch Limit**: Maximum 10 images per batch request
3. **Response Time**: API response time ≤ 3 seconds; operations exceeding this use async task handling
4. **Rate Limiting**: Free plan: 10 req/min, Starter: 60 req/min, Pro: 120 req/min
5. **No Alt Text Generation**: The external API does NOT generate alt text — this must be done by the Agent's local LLM
6. **No Schema Generation**: JSON-LD structured data must be generated by the Agent's local LLM
7. **No Listing Generation**: Product listing copy must be generated by the Agent's local LLM
8. **Sandbox Keys**: Limited to 10 total API calls (for testing only)

## 迁移说明（v1.6.1 重要变更）

> **旧工作流必须升级，否则 API 调用将失败。** v1.6.1 起，`privacy_accepted` 从隐式默认 `true` 改为**显式必填**，默认值为 `false`。

### 变更内容

| 变更项 | 旧行为（≤ v1.5.x） | 新行为（v1.6.1+） |
|--------|-------------------|-------------------|
| `privacy_accepted` | 默认 `true`，可选 | 必须显式传入 `true`，否则 API 拒绝请求 |
| 图片格式校验 | 仅客户端校验大小 | 服务端 + 客户端双重校验（魔数 + 大小） |
| 废弃工具 | 含 `generate_schema_markup`、`generate_ai_listing` | 已移除，由 Agent 本地 LLM 替代 |
| `title` / `product_type` 参数 | process_image 接受 | 已移除，不再需要 |
| `generate_alt` 参数 | 可选 | 已移除，Alt 文本由 Agent 本地 LLM 生成 |

### 升级步骤（4 步）

**第 1 步：更新 Dify 工作流**

在 `process_image` / `batch_process_images` 节点中，确保 `privacy_accepted` 参数设置为 `true`：

```
# Dify 工作流节点配置
privacy_accepted: true   # 必须显式设置，不能留空
```

**第 2 步：更新 Coze Bot 配置**

在 Coze 技能调用代码中，所有 `process_image_json()` 和 `batch_process_images()` 调用必须包含 `privacy_accepted=True`：

```python
# 正确示例
result = process_image_json(
    image_base64="...",
    remove_bg=True,
    compress=True,
    privacy_accepted=True,   # 必须显式传入
)
```

**第 3 步：移除废弃参数**

从所有调用中删除以下参数（现已不支持）：
- `title` — 不再需要
- `product_type` — 不再需要
- `generate_alt` — 已硬编码为 `False`

**第 4 步：验证**

升级后，确认以下各项通过：
- [ ] Dify 工作流运行时 `privacy_accepted` 已设为 `true`
- [ ] Coze Bot 所有调用包含 `privacy_accepted=True`
- [ ] 不再引用 `generate_schema_markup` / `generate_ai_listing` 工具
- [ ] 图片处理正常返回 `processed_image_base64`

### 常见问题

**Q: 不升级会怎样？**
A: API 将返回 400 错误，提示 `privacy_accepted` 为必填字段。

**Q: 为什么 privacy_accepted 默认改为 false？**
A: GDPR 合规要求，用户必须主动选择同意（opt-in），不能预设为同意。

## Privacy

See [PRIVACY.md](./PRIVACY.md) for full details.

**Key points:**
- Images are processed in transient memory and cleared immediately (0 seconds) after processing
- Alt text, Schema, and Listing are generated locally — never sent to external API
- API Keys are SHA256 hashed with random salt
- All communication is encrypted via HTTPS (TLS 1.3)
- `privacy_accepted` must be set to `true` by the user (opt-in) in every API request
